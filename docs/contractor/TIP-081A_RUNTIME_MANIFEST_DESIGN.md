# TIP-081A — Complete runtime acquisition and acceptance design

2026-10-07. SAME081 Phase A, two-stage packaging. This is a source-backed
design checkpoint, not a runtime grant or completeness certificate.
The first implemented prerequisite in this routing is actual normalized config
proof, TIP-081A_CONFIG_PROOF.md. Full T2–T5 remain OPEN until their own evidence.

## Decision

Use a reviewed, explicit, source-bound runtime manifest as acceptance authority.
Any stock NFT output is only a discovery candidate, never self-certifying
complete. Do not remove current product refusal just because callbacks or flags
pass tiny tests. Do not write a partial real package and call it standalone.

Installed Next16.2.11 output guide admits tracing limitations; collect-build-traces
uses runtime-specific entries/ignores, and copyTracedFiles emits a distinct launcher.
Installed NFT's default filesystem dynamic/special/native paths bypass supplied
callbacks. evaluatePureExpressions=false prevents its node-gyp helper evaluation
branch but can lose needed assets; it does not establish coverage. Independent
Builder scan and read-only peer agree that these are separate obligations.

## Pipeline / trust boundary

Source-bound input snapshot -> data-only dependency acquisition
-> candidate manifest with unresolved obligations
-> independent coverage review/verifier
-> complete bounded copy plan -> all-regular private output.

The final two steps remain disabled until complete admission; runtime start and
browser E2E require separate future approval and successful fresh-build evidence.
No step is authorized by an old failed-build marker or this Markdown document.
Keep candidates/rejections/source epochs append-only.

## D1: Exact profile and immutable inputs

Bind installed Next16.2.11 tool bytes, Node version/platform/arch, lock digest,
reviewed source bundle and predecessor pairs, normalized accepted config, generated
build inventory and original raw trace digests. Bind production/isDev:false profile,
fixed distDir and supported route set. Missing/mutated/foreign profile refuses.

Retained failedbuild4 QGsthQ may support feasibility only; it cannot become a
successful-build receipt or launchable product through supplemental tracing.
After a later approved successful build, reconstruct/revalidate every generated
input against that new epoch. Never recycle an old scientific source approval.

## D2: Complete entry and file universe

Derive and verify all entries from generated route/pages/app manifests and
required-server-files, not a handpicked Studio route. Preserve all57 incomplete
predecessor NFT inventories and every regular reference as explicitly labelled
inputs, never silently discard them. Bare link entry is invalid as a file.

Required seed classes:

- Root package.json and its CJS/ESM/module/export/import semantics.
- Safe generated server tree including chunks, app/pages, route vendored contexts;
  required-server-files.files and its manifest; static/public.
- next/package.json, next start-server/next/require-hook/next-server runtime
  entrypoints, styled-jsx override targets and jest-worker children.
- Middleware files/wasm/assets and instrumentation as declared in real manifests.
- Exact reviewed fonts (NotoSans Regular/Bold), Prisma runtime metadata/assets
  and every other runtime native/data dependency reachable under the fixed profile.
- A fresh source-derived root launcher, never failed standalone/server.js.

Next canonical ignores are profile-specific evidence to audit, not arbitrary
exclusions to meet a cap. In particular changing output to undefined removes
Next's standalone-only trace seeds; the acquisition must deliberately restore
runtime worker/bootstrap seeds. Compilers are neither blindly included nor
blindly excluded: actual runtime reachability decides, with unresolved reachability
remaining OPEN.

## D3: Data-only acquisition

Preferred first producer: reviewed JS/JSON parser and package resolver that
interprets syntax and Node package conditions as data. No require/import of
application or package helper code, native loading, lifecycle scripts, child
processes or environment-directed callbacks. No regex-only universal import proof.

Each dependency edge records importer digest/location, syntax, literal/finite/
dynamic classification, specifier, condition/alias rule, exact resolved path and
package boundary metadata. Resolve CJS/ESM, exports/imports, relative/absolute paths,
require-hook overrides, context modules and conditional branches explicitly.
For dynamic imports/filesystem reads: resolve an exact finite declared set or
emit an unresolved obligation identifying the source location. Never substitute
an unreviewed recursive glob. Optional dependencies and caught errors need
semantic dispositions; ignoring a warning is not a coverage disposition.

All source reads/no-follow ancestors/links/special files/file identities/hashes
are checked. A resolver denied access cannot assume the path absent.
The source universe and byte/entry accounting precede any execution or copy.

## D4: Stock NFT sidecar, if ever admitted

It can produce untrusted candidates only. Before an actual invocation, prove
module loading is limited to pinned analyzer plus stdlib; no target/helper/native
evaluation. All I/O must be brokered or physically staged with exact nofollow
inventory and independent whole-directory bounds, including directfs/defaultglob.
OS read-only/no-network/process denial is defense in depth, not proof of
evaluation-freedom or complete callbacks. Every denied read/suppressed failure
must become an explicit coverage failure.

If those properties cannot be established, DO NOT execute stock NFT on product
inputs and DO NOT patch installed Next/NFT. Use data-only/manual manifest acquisition.
No such sidecar is executed/authorized at this design checkpoint.

## D5: Coverage certificate, independently checked

Manifest authority is not “a reviewer filled a JSON field.” The independent
verifier must reconstruct the bound entry/file universe and validate every
resolution edge, package boundary/condition, alias, source-site disposition,
explicit asset/native/shared-library inclusion and exact output path.
Unknown source locations, unhandled AST syntax/dynamic expressions, missing
transitive files, unclassified native/shared-library dependencies, unresolved
optional/branch evidence or inaccessible reads keep status OPEN/REFUSED.

Record separately static resolution, reviewed semantic branch assumptions,
finite operational checks and universal claims. This is a fixed QA-profile
deployment certificate, not proof of all arbitrary Next/application executions.
Human/Main semantic acceptance plus source audit is explicit; hashes and test
votes alone do not establish completeness.

## D6: Launcher and runtime parity

Generate the root launcher from pinned installed utils.js copier semantics and
the new required-server configuration. Bind source/template/config digests.
Preserve CJS-vs-ESM envelope, cwd, production default, __NEXT_PRIVATE_STANDALONE_CONFIG,
distDir relocation, require('next'), startServer isDev:false/allowRetry:false and
keepAlive validation. No .env copy or serialized secret/config leakage.

Keep a separately reviewed QA test-mode envelope for later authenticated browser
acceptance; do not silently rewrite product production semantics. Current
start-tip081-standalone.mjs is historical/build4-bound and must not accept a new
package receipt without an explicit compatible successor contract.
Do not execute the generated launcher during offline manifest acceptance.

## D7: Copy budget provenance and physical output

Inherited source/public/static copyTree8MiB and regular dependency remaining64MiB
rules are distinct. Current helper universal8MiB/combined snapshot+output64MiB are
provisional Main guards; retained13MiB route is not an Owner cap violation.
Before actual product planning, settle an explicit category/accounting policy
without silently widening the approved aggregate/resource envelope. No fit claim
until actual complete manifest sizes are known, including launcher/metadata.

Materialize only a complete authorized plan into exact owned UID0700 private
root. Create-only independent regular files, no link/hardlink/original write;
complete before/after hash+device/inode+nlink+inventory checks. Include all config/
launcher/manifests/assets, reject unexpected/missing files. A failed epoch cannot
be relabelled successful; incomplete plans cannot get materialization authority.

## D8: Evidence and routing

Acceptance order:

1. Actual T1 normalized config comparison (current bounded implementation).
2. Source-only producer/resolver/manifest/verifier/launcher contracts reviewed.
3. Separately scoped complete product read-only acquisition; unresolved sites
   reported precisely, not replaced with additional tiny successes.
4. Complete manifest/coverage/copy-policy acceptance and actual independent
   physical output verification, without running app/server.
5. Only then a separately approved fresh build and conditional authenticated E2E.
