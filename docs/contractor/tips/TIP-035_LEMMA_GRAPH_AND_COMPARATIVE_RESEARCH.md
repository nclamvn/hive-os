## Blueprint

### A. Root-bound mathematical dependency graph

Fresh eligible autonomous portfolios use trusted `ADAPTIVE_RESEARCH_V2` and portfolio version 3. Preserve V1/V2 portfolios and `ADAPTIVE_RESEARCH_V1` command/event/selection semantics without rehashing old records or upgrading them on read. New policy is bound in CommandRecord outcome/outbox and declaration, exactly as the existing downgrade-resistant trusted seam; absence/stripping of required graph must not silently permit legacy admission.

Decision G-SCOPE: new HUMAN_STEERED single-proposal requests retain the existing adaptive V1 path. They do not silently acquire synthesized lemma graphs. Graph-required policy applies to new autonomous portfolios only, as scoped above; no extra proposal schema/call is added for the separate steering mode.

Planner emits a bounded graph for each portfolio branch within the existing call. The server seals root/cycle/method/branch identity; the exact root statement/contract is server-owned. Graph node fields include exact statement version/digest, variables/domain, ordered quantifiers, explicit assumptions, finite versus universal scope and finite bounds if applicable. Hyperedges name all premise nodes, conclusion and claimed justification/relation. Structural validators enforce IDs, references, bounds and DAG; this does NOT prove the mathematical implication.

Decision G-CONNECTION: all nodes must be connected to ROOT in the underlying undirected dependency graph, but do not require every node to imply ROOT. A useful necessary-condition direction ROOT→lemma can be explored while its reverse bridge remains missing. Preserve directed orientation/DAG and visibly distinguish missing forward root bridge from a merely claimed forward path; neither is verified proof. Forcing a sufficient implication in every proposal would encourage fabricated bridges.

Model output cannot author verified edge status. Every new edge starts as a claimed relation with unresolved semantic alignment. Existing coarse workflow obligations remain historical workflow, not proof authority; `ROUND_CLOSED` must not imply a lemma was proved. Existing independent typed refutations remain exact registered predicates, not semantic refutations of arbitrary prose. Finite arithmetic, AI-reviewed informal argument, formal kernel acceptance and alignment each remain separate evidence dimensions. No universal root-complete/theorem flag may be inferred from a well-formed graph or all-positive AI reviews.

The graph is retained in the sealed V3 portfolio and supplied through the existing actual worker contexts to source roles, verifier, solver and peer reviewers. The verifier must explicitly consider root connection, assumptions and quantifier/scope mismatch; its natural-language assessment remains AI assessment. Any missing graph in a new-policy portfolio stops before downstream dispatch. No extra model calls or arbitrary runtime code.

### B. Executable comparative experiment framework

Seal the plan BEFORE any execution: cases/contracts, source and tool snapshots, model/request settings, exact three lanes `SINGLE_LLM`, `TOOL_FIRST`, `ADAPTIVE`, repeated-case ordering, same token/time/tool envelopes, exposure labels, stop rules and scoring reference digests. Default cases are explicitly public/development controls; no private held-out claim.

Solver projection excludes scoring answers/labels/rubrics. Reviewer receives a blinded attempt projection only after its attempt is sealed; policy/lane/session/usage labels are stripped where not essential to assessment, and exposure limits are stated. Evaluator dimensions distinguish affirmative accept, affirmative reject and abstention. Incorrect acceptance/rejection needs a matching known oracle and actual decision; an inconclusive response is not automatically a false rejection.

Use a shared budget broker for all lane operations, including planner/source/reviewer calls and fixed tools. Retain pending-before-execution plus outcomes, monotonic elapsed time, usage KNOWN/UNKNOWN and token accounting provenance. Sum input+output only; cached/reasoning fields are subsets. Unknown failed/ambiguous usage stops the lane and makes accounting/comparison incomplete. Retain threshold overshoot and prohibit another call; observed-token threshold is not a hard monetary cap. Deadline/cancellation must not turn a still-running executor into a successful clean stop. Output bounds, repeated session/call identity and complete lane/case coverage are checked. Fixed offline fixtures use SIMULATED tokens and real observed framework time, not invented live model latency.

Shipped CLI runs only fixed OFFLINE_FIXTURE scenarios or verifies bounded inert retained JSON. No dynamic imports, shell/model/provider execution selected by data. Injectable executors are an explicit trusted test seam, not a claim that arbitrary imported receipts are authenticated. Externally supplied untrusted receipts remain UNATTESTED. Digests bind content; they do not certify live execution or mathematical validity. Output must retain `scientificYield: NOT_MEASURED` for this slice.

### C. Bounded authorized dossier UI

Replace full-body-first page loading with mission-scoped summaries, separate calibration records, bounded visible details and bounded full cycle counts. A selected authorized case may be retrieved even if not on the summary page. Do not pass untrusted query IDs into cross-mission/tenant retrieval. Deterministic ordering/cursors, invalid/duplicate query rejection and visible pagination/completeness labels are required.

Calibration readiness remains independent of presentation selection and cannot silently ignore an older valid calibration because a recent case is pending. No partial event-chain prefix is validated as full history. New selected-case reads may retrieve full event chains only for authorized displayed cycles; no arithmetic replay/tool/model/source fetch on GET. Limit job/outbox queries to displayed cases/formal attempts. Reuse existing indexes and no migration. Retain current single-flight/visibility-aware refresh.

Decision H-BOUNDS: summary pages contain at most 20 records; default detailed display is the latest one authorized case, or the exact authorized selected case even off-page. Cycle pages contain at most three complete validated chains with total/cursor. Calibration scans bounded pages of plausible completed records, at most 200 candidates; reaching its safety ceiling without establishment is explicitly INCOMPLETE/NOT_ESTABLISHED and fail-closed, not proof that no valid historical calibration exists. Selection never changes that scan. Summary-only metadata is not a mathematics verification badge.

Decision H-READ-INTEGRITY: on-read canonical/hash/schema checks and bounded direct BigInt identity/strictness checks of already retained witness tuples are allowed evidence integrity checks, not discovery. Do not downgrade historical exact-identity display merely to avoid a tiny static check. New enumeration, factor searches, two-gate diagnostics, Python/Lean/source/model calls remain forbidden on Math Pilot GET. Never weaken old full-chain integrity validation; any hidden historical recomputation cost must be reported separately.

Decision H-CALIBRATION-CONSISTENCY: the existing authoritative calibration prerequisite query may be narrowly aligned with the same bounded plausible-completed-candidate predicate and unchanged integrity validator used by UI. Revalidate inside its existing trusted transaction, never trust UI readiness or create nested tenant transactions. Pending rows must not crowd out older valid completed evidence; safety-cap uncertainty fails closed. No other mutation semantics change. This avoids a passed UI indicator paired with an unrelated latest-500-pending command lookup.

Decision H-ACTIVE-CALIBRATION: duplicate-dispatch presentation must also remain independent of the selected detail. Two bounded mission/workspace/organization/provider/model-scoped active-calibration ID lookups may supply card availability using existing active-status semantics. No unrelated case bodies, new runtime action or weakened authoritative gate.

UI reuses locked restrained design/typography/MathText/KaTeX and VI/EN labels. Graph panel distinguishes claimed implication, unresolved assumption and evidence ceiling, with exact source disclosure. No decorative “theorem solved” score. Full historical content remains accessible through explicit bounded navigation, not deletion.

Decision UI-COPY: the queue-disabled VI/EN banner must describe the actual governed AI-role workflow, not falsely require a second human account to launch AI research. Worker/provider/resource authorization stays required; optional human academic review, formal alignment and novelty gates remain distinct and unchanged. This is a copy correction only, not new launch authority.
