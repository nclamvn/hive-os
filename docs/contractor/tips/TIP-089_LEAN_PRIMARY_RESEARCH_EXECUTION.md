## Requirements / acceptance

R1 Primary-first: one primary invocation when no concrete gap. No mandatory
self-check, critic or final-rewrite calls. Preserve immutable original output.

R2 Specific criticism: a bounded gap identifies the actual claim/step and issue,
not confidence, decorative wording or a generic 'please review'. A compatible
failed/inconclusive tool check is concrete evidence; a solver-declared missing
lemma/step is another. Critic receives the exact problem, draft and selected gaps.
No critic on an already exactly checked obligation just to collect a vote.

R3 Tool scope: reuse an installed checker only for its compatible domain/candidate.
Host checked witness/identity/finite coverage is exact scope only, never a global
theorem or novelty claim. Unsupported proof/Lean/tool scope remains explicitly
unestablished; prose and an AI review cannot mint a host receipt. Distinguish a
rejected candidate from a refuted exact predicate. No checker growth/installation.

R4 Failure resilience: optional critic/repair timeout, malformed output or unchanged
proposal must not erase a primary draft or earlier valid certificate. Keep both
original and attempted revisions. A rejected/inconclusive revision cannot replace
a stronger verified result; report unresolved gaps/failures without success washing.

R5 Bounded execution: at most primary+one targeted critic+one repair (3 model calls),
optional budget may disable secondary calls; one overall deadline/output cap,
abortable port calls, at most two compatible checks. No hidden retry, loop or budget
reset. Retain actual per-call usage; missing remains null/UNKNOWN, not0. Host caller
owns ports/limits/retention; developer tooling is not a sandbox or execution grant.

R6 Usable entry point: thin runnable CLI for controlled fixture/retained-output
replay with explicit synthetic/replay provenance and no network/model charge.
Exercise no-gap fast path, check success, targeted failed-check repair, optional
failure retaining primary and unsupported argument scope. Connect to existing
research:check and its scoped types/tests, without another test/build configuration
family. Explain how a real authorized provider implements the port, without pretending
that fixture replay called an LLM. Keep UI/server untouched in this scope.

R7 Preservation: auth/tenant/source/lease/commitment gates, oldp139/R3, frozen
pilot088 sources/receipts, pre-existing dirty files and old failed attempts stay
unchanged. No new schema/dependency/framework, real API/CLI mathematical solve,
DB write, build, Git, deployment or campaign. Existing source bundles do not gain
authority by this developer implementation.
