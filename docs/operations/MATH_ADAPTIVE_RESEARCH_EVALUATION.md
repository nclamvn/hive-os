# Adaptive mathematical research: evaluation protocol

Date: 2026-10-01. Linked implementations: TIP-034 and TIP-035. This document is a protocol, **not a completed scientific evaluation**.

## What implementation tests can and cannot establish

Fixtures establish source-status isolation, provenance, policy replay, safe routing and retained outcomes. They do not establish theorem discovery, exhaustive literature coverage, model independence or improvement in mathematical ability. A source with no observed withdrawal is not a proof certificate. An independently checked numerical witness is not a universal theorem.

The four heavily investigated Erdős–Straus targets and all existing G/H packets are development/warmup controls. Their hits, misses and hand-designed method cards must not be relabeled held-out research successes. The public IMO example is likewise a known-answer calibration, not a general IMO score.

## Preregister the next comparison before execution

Seal the target contracts, input statements, corpus snapshot/source health, exact provider/requested model settings, tool versions, reviewer exposure, resource envelope, run count and stopping rules. Keep anticipated solutions and scoring labels out of solver prompts. State any prior model exposure; an unfamiliar problem to the application is not necessarily unfamiliar to its pretrained model.

Compare three lanes under the same total observed-token threshold, time boundary and tool permissions:

1. A single LLM with the same source packet and tools.
2. The historical tool-first portfolio policy.
3. The new relevance-first adaptive policy.

Retain per-call actual usage and wall time, including failed or ambiguous calls. Thresholds checked before calls can overshoot in flight and are not hard monetary caps. No lane receives hidden additional human derivations or extra computation. If orchestration costs use more of the budget, report that rather than increasing its allowance after seeing outcomes.

Use a versioned suite, not a single favorable demonstration: known-result reconstruction, intentionally misleading premises, narrow subproblem lemmas and genuinely exploratory targets. A separate curator should freeze any claimed held-out suite before planners/reviewers see its labels; no such private held-out suite is accepted by this implementation slice.

## Scientific outcomes to record separately

- Correct known-result reconstruction with its actual hypotheses.
- Exact counterexample and independently replayed predicate, with scope limits.
- Informal useful lemma, unresolved proof gaps and independent mathematical review.
- Kernel-accepted formal statement, axiom audit and outstanding semantic alignment.
- Contribution to the root: explicit checked implication or an honestly missing bridge.
- Prior-art match, source conflict/withdrawal, and novelty still unestablished.
- False accepts and false rejects; repeated branches and budget lost to unusable work.
- Routing response to negative or inconclusive information; deferred tools retained.

Never collapse these into a single model confidence or “breakthrough percentage.” Density/average results do not by themselves eliminate an exceptional set. More decompositions of already solved fixed inputs do not establish new root coverage.

## Executable development control (TIP-035)

The standalone comparator now provides a sealed three-lane offline control, budget accounting, retained attempts and reviewer projections, and inert-JSON integrity verification. Its fixed responses exercise orchestration; they do not run the production adaptive agents or measure mathematical capability. All lanes receive the same canned mathematical responses. Tokens are **SIMULATED**, framework wall time is observed, and scientific yield is **NOT_MEASURED**. A valid imported JSON hash is not runtime or model attestation.

See [the comparator runbook](MATH_COMPARATIVE_OFFLINE_FRAMEWORK.md) for safe fixture commands and the implementation's test-seam limits. Connecting a real executor, curating and freezing an appropriate evaluation suite, and authorizing actual resource use are separate prerequisites for the scientific comparison described above. Do not infer that the adaptive lane wins merely because it performs more planner or tool calls.

TIP-035 also retains a goal–lemma graph in new autonomous policy-V2/portfolio-V3 campaigns. Each proposed implication or research dependency remains **CLAIMED / UNRESOLVED**. Undirected connectivity to the sealed root admits necessary-condition research without inventing a reverse implication. A connected, acyclic graph does not prove any edge, discharge semantic alignment, or certify the root theorem.

## Go/no-go for a further research campaign

Proceed when source dependencies have admissible provenance, the selected direction exposes a concrete unresolved bridge, and the next experiment can discriminate between alternatives inside the authorized runtime envelope. Revise or retire a direction when it repeats a refuted claim, depends on a quarantined source as accepted truth, or only generates more warmup counts without answering its declared question.

Changing a mathematical representation or method family within the approved root may be AI-operated. A materially different root problem, new external spend/tool authority, publication-level semantic acceptance or public novelty claim still needs the relevant human decision. A deferred tool requirement is not permission to execute generated code.

## Current acceptance ceiling

TIP-034/TIP-035 may be accepted as local method/software upgrades after regression and integration verification. Their scientific yield remains **NOT_MEASURED** until a separately retained, budget-matched campaign has been executed and assessed. No new theorem, novelty, live model campaign or root breakthrough is claimed by this protocol.
