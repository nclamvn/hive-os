## Delivered execution boundary

Producer uses separately derived bitset/private-time state; checker uses scalar
sets, not producer/host helpers. Each genuinely closeable row iterator captures
its generation fence AT CALL, including before its first next(), precharges
sorting and aggregate live-reader workspace, and releases on close/error/EOF.
Snapshots and barrier hashes consume rows without raw compatibility copies.
Current/empty support tables, repeated extras and final UNION retain075C meaning.
The checker requires independently derived rows and supplied rows through BOTH
genuine EOFs. Exact keys/width/range/order/distinctness/multiplicity, same-cut
verified marker and terminal state are mandatory; feed invalidates that marker.
Failures poison publication rather than allowing a caught exception to certify.

Host streams one descriptor and bounded blob chunks over inert tag/u64 frames.
No all-prefix list, JSON/base64 payload or path authority enters a child. ONE
outgoing event segment is buffered under its declared cap; a pre-next-event
46-byte guard prevents applied but unpublished events. TABLEs arrive in numeric
order then DATA; hash/length/order/count are checked at their real EOF. Parent
spools stdout to an owned create-only file while simultaneously draining bounded
stderr and pumping lazy stdin; parses only after exit0, EOF, no stderr and
before/after source-pin equality. Child executes the SAME checked OWN bytes with
Python -I -S -B and exact six false flags, not a later reopened source path.

Every normal advance permanently reserves HOST_AUDIT -> VERIFY -> GENERATE ->
VERIFY before START: four reservations, three actual child processes. AUDIT is
blob integrity, not a semantic verdict. All children reconstruct every retained
event from genesis; no saved cursor/receipt is semantic state. Durable no-follow,
exclusive locking, regular single-link files, create-only names, fsync and
commit-LAST retain captured unaccepted evidence. Only an intact successful GEN
receipt/tail can get a NEW charged verification-only recovery. Orphan reservation,
START, staging, bad/error/missing receipt or inconsistent ledger STOP, without
rollback, quota refund or automatic retry. Inspection is explicitly metadata-only
and cannot reuse a historical positive verdict as fresh verification.

Main review additionally routed fixes for unreserved bootstrap/final metadata
walk, carried deadline/I/O, pre-read stdout/stderr allowance, pre-next segment
admission, scalar/JSON preparse guards, source/FD failures, and cleanup that must
attempt every owned pipe/selector/generator/file even after a close/fsync fault.
The final receipt precharges its full raw length once before partial-write retries
and includes its own conservative chargedIo; reservation TOTAL is never rebased.
